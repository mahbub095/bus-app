SonyaBus — Bus Ticket Booking System

Full-stack booking platform · Laravel 12 backend · React 19 customer app · ZiniPay payments · SMS notifications

Introduction

SonyaBus is a complete bus ticket booking system with two separate surfaces:

  • Customer React app — search schedules, choose seats on an interactive seat map, pay online, manage tickets, apply promo codes.
  • Laravel Admin dashboard — manage coaches, routes, schedules, bookings, cancel requests, promotions, users & roles, reports (PDF & Excel), and all gateway settings.
ItemDetail
BackendLaravel 12, PHP 8.2+, MySQL / SQLite
FrontendReact 19, Vite 8
PaymentZiniPay
SMSSMS.NET.BD, BulkSmsBD, or custom GET/POST gateway
AuthLaravel Sanctum (customer API) + session (admin)
Reports11 report types — PDF (DomPDF) & Excel export

License Activation

SonyaBus requires a valid CodeCanyon purchase code to operate. Activation happens through the built-in installation wizard the first time you open the app. The application will automatically redirect every request to /install until a license is verified.

What you need

ItemWhere to find it
Purchase Code Envato Market → Your Account → Downloads → click Licenses & Purchase Codes next to SonyaBus
Personal Token Generate at build.envato.com/create-token. Enable the Verify Purchases permission. The token is used once during verification and is never stored.

Activation wizard — steps

  1. License — Enter your purchase code and Envato personal token. The system calls the Envato Market API to confirm the code belongs to this product.
  2. Database — Enter your MySQL host, port, database name and credentials. A live connection test is performed before saving.
  3. Admin Account — Create the initial super-admin login (name, email, password).
  4. Finalize — Runs php artisan migrate, creates the admin account, and clears all caches. You are redirected to the admin dashboard.
✅ After activation the wizard is no longer accessible to unauthenticated visitors. Your .env file is updated with APP_LICENSED=true automatically.

Re-verifying after a domain change

If you migrate to a new domain, go to Admin → License (super admin only) and enter your purchase code and a new Envato personal token. The license record will be updated with the new domain.

⚠ One purchase = one live installation. A Regular License covers a single end product for a single client. Purchase an Extended License or additional Regular Licenses for multiple deployments. See the Envato license terms for details.

Installation

Step 1 — Upload & extract

Upload the package ZIP to your server and extract it. You should have a backend/ and a frontend/ directory.

Step 2 — Install backend dependencies

cd backend
composer install --no-dev --optimize-autoloader

Step 3 — Configure backend environment

cp .env.example .env
php artisan key:generate

Edit backend/.env and set at minimum: APP_URL, APP_FRONTEND_URL, DB_* credentials, and ENVATO_ITEM_ID (your CodeCanyon item ID). See the Backend .env section for all values.

ℹ ENVATO_ITEM_ID is the numeric ID in your CodeCanyon item URL:
https://codecanyon.net/item/sonyabus/12345678 → set ENVATO_ITEM_ID=12345678

Step 4 — Set storage permissions

chmod -R 775 storage bootstrap/cache
chown -R www-data:www-data storage bootstrap/cache

Step 5 — Configure your web server

Point your web server to backend/public/. See the Web Server section for Nginx and Apache examples.

Step 6 — Run the Installation Wizard

Open your backend URL in a browser. You will be automatically redirected to the installation wizard at https://your-backend-domain.com/install. Complete all 4 steps: License → Database → Admin Account → Finalize.

The wizard will run database migrations and create your super-admin account.

⚠ After installation, the wizard creates demo data only if you ran php artisan db:seed manually. The wizard itself does not seed demo data — your database starts clean.

Step 7 — Install & build the frontend

cd ../frontend
cp .env.example .env
# Edit frontend/.env — set VITE_API_BASE_URL and VITE_ZINIPAY_API_KEY
npm install
npm run build

The compiled app will be in frontend/dist/. Point your web server document root here for the customer-facing site.

(Optional) Seed demo data

To populate the system with sample stations, routes, schedules, and user accounts for testing:

php artisan db:seed
🔴 Never seed on a live production database. The seeder creates demo accounts with password password123.

cPanel Installation

Follow these steps to install SonyaBus on shared hosting (Hostinger, Namecheap, Bluehost, etc.) that comes with cPanel.

⚠ Requirement: Your cPanel must have PHP 8.2+ and either SSH / Terminal access or the Composer Manager plugin. Most modern shared hosting plans include cPanel Terminal.

Step 1 — Create Two Subdomains

SonyaBus keeps its backend and frontend on separate domains/subdomains. Create them from cPanel → Domains / Subdomains:

PurposeSubdomain ExampleDocument Root
Backend (Laravel API + Admin) api.yourdomain.com public_html/api/public
Frontend (React App) app.yourdomain.com public_html/app
ℹ Alternative: You can use the main domain instead of separate subdomains. In that case yourdomain.com → frontend, but it is still recommended to keep api.yourdomain.com → backend rather than yourdomain.com/api.

Step 2 — Upload Files

  1. Prepare ZIPs: On your computer, separate the project into two folders — backend.zip and frontend.zip.
  2. Open cPanel → File Manager. Go to the public_html/ folder.
  3. Upload backend.zip and extract it into the public_html/api/ folder.
    This will create: public_html/api/app/, public_html/api/public/, etc.
  4. Upload all contents of frontend/dist/ into the public_html/app/ folder.
    (Upload the files inside the dist folder, not the dist folder itself)
ℹ Build the dist folder: To build the frontend on your local machine: 
cd frontend
npm install
npm run build
Upload all files from the generated frontend/dist/ folder to cPanel.

Step 3 — Fix the Subdomain Document Root

cPanel → Domains → the Document Root for api.yourdomain.com must be public_html/api/public — not public_html/api. Otherwise Laravel will throw a 500 error.

Step 4 — Create the .env File

cPanel File Manager → go to the public_html/api/ folder. Copy the .env.example file and name it .env. Then edit it: 

APP_ENV=production
APP_DEBUG=false
APP_URL=https://api.yourdomain.com
APP_FRONTEND_URL=https://app.yourdomain.com
ENVATO_ITEM_ID=12345678   <-- your CodeCanyon item ID

DB_HOST=localhost
DB_PORT=3306
DB_DATABASE=yourusername_sonyabus   <-- cPanel database name
DB_USERNAME=yourusername_dbuser     <-- cPanel database user
DB_PASSWORD=your_db_password

Step 5 — Create a MySQL Database

cPanel → MySQL Databases:

  1. Create a new database, e.g. yourusername_sonyabus
  2. Create a new user, e.g. yourusername_dbuser — use a strong password
  3. Give the user ALL PRIVILEGES on the database

Step 6 — Run Composer from Terminal

cPanel → Terminal (or an SSH client like PuTTY):

# go to the backend folder
cd public_html/api

# generate APP_KEY
php artisan key:generate

# install dependencies
composer install --no-dev --optimize-autoloader

# create storage link
php artisan storage:link
⚠ If Composer is not available: Use Softaculous in cPanel or your hosting provider's "Composer Manager". Alternatively, run composer install --no-dev on your local machine and upload the project including the vendor/ folder.

Step 7 — Check the Backend .htaccess

Check whether the public_html/api/public/.htaccess file exists. If not, create it with the following: 

<IfModule mod_rewrite.c>
    <IfModule mod_negotiation.c>
        Options -MultiViews -Indexes
    </IfModule>

    RewriteEngine On

    # Handle Authorization Header
    RewriteCond %{HTTP:Authorization} .
    RewriteRule .* - [E=HTTP_AUTHORIZATION:%{HTTP:Authorization}]

    # Redirect Trailing Slashes If Not A Folder...
    RewriteCond %{REQUEST_FILENAME} !-d
    RewriteCond %{REQUEST_URI} (.+)/$
    RewriteRule ^ %1 [L,R=301]

    # Send Requests To Front Controller...
    RewriteCond %{REQUEST_FILENAME} !-d
    RewriteCond %{REQUEST_FILENAME} !-f
    RewriteRule ^ index.php [L]
</IfModule>

Step 8 — Create the Frontend .htaccess

Create public_html/app/.htaccess for the React app (needed to redirect all requests to index.html for React Router): 

<IfModule mod_rewrite.c>
    RewriteEngine On
    RewriteBase /

    # Don't rewrite files or directories
    RewriteCond %{REQUEST_FILENAME} -f [OR]
    RewriteCond %{REQUEST_FILENAME} -d
    RewriteRule ^ - [L]

    # Rewrite everything else to index.html
    RewriteRule ^ index.html [L]
</IfModule>

Step 9 — Run the Installation Wizard

Open https://api.yourdomain.com in your browser. You will be automatically redirected to /install. Complete all 4 steps: License → Database → Admin → Finalize.

Step 10 — Set Up the Cron Job

cPanel → Cron Jobs → "Add New Cron Job":

* * * * * /usr/bin/php /home/yourusername/public_html/api/artisan schedule:run >> /dev/null 2>&1
ℹ PHP path: The PHP binary path may differ on your hosting. Run which php in the Terminal to find out.

Step 11 — Set Up the Queue Worker

For the SMS notification queue. cPanel → Cron Jobs:

* * * * * /usr/bin/php /home/yourusername/public_html/api/artisan queue:work --stop-when-empty >> /dev/null 2>&1
⚠ Shared hosting limitation: Most shared hosting does not allow persistent background processes. Therefore use queue:work --stop-when-empty instead of queue:work and run it every minute via cron.
✅ All done! Now https://api.yourdomain.com/admin → admin dashboard, https://app.yourdomain.com → customer app.

Local Machine Installation (Laragon / XAMPP)

Set up a local development environment on Windows using Laragon or XAMPP. Laragon is the easiest and recommended option.

Option A — Laragon (Recommended)

Step 1 — Install Laragon

  1. Download and install Laragon Full (6.0+) from laragon.org/download. It comes with PHP 8.2, MySQL, Apache, Composer, and Node.js.
  2. Start Laragon → click Start All.

Step 2 — Place the Project

Laragon's default root folder: C:\laragon\www\
Place the project folder at: C:\laragon\www\bus-app\ 

C:\laragon\www\bus-app\
├── backend\      <-- Laravel
└── frontend\     <-- React

Step 3 — Create the Database

Click the Database icon in Laragon (HeidiSQL will open). Left panel → right click → Create new → Database → name it sonyabus.

Step 4 — Set Up the Backend

Open Laragon Terminal or Windows Terminal:

cd C:\laragon\www\bus-app\backend

# create .env
copy .env.example .env

# generate APP_KEY
php artisan key:generate

Edit the .env file with Notepad++ or VS Code:

APP_ENV=local
APP_DEBUG=true
APP_URL=http://bus-app.test/api   # or http://localhost:8000
APP_FRONTEND_URL=http://localhost:5173
ENVATO_ITEM_ID=12345678

DB_CONNECTION=mysql
DB_HOST=127.0.0.1
DB_PORT=3306
DB_DATABASE=sonyabus
DB_USERNAME=root
DB_PASSWORD=        # no default password in Laragon
# Composer dependencies
composer install

# Storage link
php artisan storage:link

Step 5 — Virtual Host Setup (Laragon Auto Virtual Host)

Laragon automatically creates virtual hosts. Go to Laragon → Menu → Apache → sites-enabled, or in Laragon → Menu → Laragon → Preferences → Services & Ports make sure "Auto Virtual Hosts" is enabled.

Laragon's Virtual Host will automatically configure itself to serve C:\laragon\www\bus-app\backend\public. Go to your browser: http://bus-app.test — but this will serve the root.

ℹ Easy way: To avoid the Laragon Virtual Host hassle, use php artisan serve (see below).

Step 6 — Start the Backend Server

cd C:\laragon\www\bus-app\backend
php artisan serve

Backend runs at: http://localhost:8000

Step 7 — Set Up the Frontend

Open a new Terminal:

cd C:\laragon\www\bus-app\frontend

# create .env
copy .env.example .env

Edit frontend\.env:

VITE_API_BASE_URL=http://localhost:8000/api
VITE_ZINIPAY_API_KEY=your_zinipay_test_key
npm install
npm run dev

Frontend runs at: http://localhost:5173

Step 8 — Installation Wizard

Open http://localhost:8000 in your browser → you will be automatically redirected to /install. Complete all 4 steps.

ℹ Local license verification: You need an internet connection to call the Envato API on your local machine. Use a real purchase code to test.

To bypass the license in development (for testing): set APP_LICENSED=true in .env and run migrations manually: 
php artisan migrate
php artisan db:seed  # optional demo data

Step 9 — Start the Queue Worker (for SMS)

cd C:\laragon\www\bus-app\backend
php artisan queue:work
✅ Local setup complete!
Admin: http://localhost:8000/admin
Customer App: http://localhost:5173

Web Server Configuration

Nginx — recommended setup

Serve the React customer app on the main domain and the Laravel API/admin on a subdomain (or same domain with path-based proxy).

# Customer React app — serves frontend/dist/
server {
    listen 80;
    server_name yourdomain.com;
    root /var/www/sonyabus/frontend/dist;
    index index.html;

    location / {
        try_files $uri $uri/ /index.html;
    }
}

# Laravel backend — serves backend/public/
server {
    listen 80;
    server_name api.yourdomain.com;
    root /var/www/sonyabus/backend/public;
    index index.php;

    location / {
        try_files $uri $uri/ /index.php?$query_string;
    }

    location ~ \.php$ {
        fastcgi_pass unix:/run/php/php8.2-fpm.sock;
        fastcgi_param SCRIPT_FILENAME $realpath_root$fastcgi_script_name;
        include fastcgi_params;
    }

    location ~ /\.(?!well-known).* { deny all; }
}

Apache — .htaccess (included in backend/public/)

Laravel ships with a public/.htaccess file. Ensure mod_rewrite is enabled and AllowOverride All is set for the document root.

DocumentRoot /var/www/sonyabus/backend/public
<Directory /var/www/sonyabus/backend/public>
    Options -Indexes +FollowSymLinks
    AllowOverride All
    Require all granted
</Directory>

Same-domain deployment (API under /api path)

If you want both on one domain (e.g. yourdomain.com → React, yourdomain.com/api → Laravel), add a proxy location to your Nginx config and set VITE_API_BASE_URL=/api.

location /api/ {
    proxy_pass http://127.0.0.1:8000/api/;
    proxy_set_header Host $host;
    proxy_set_header X-Real-IP $remote_addr;
}

Admin Panel Overview

Access the admin panel at /admin/login with an admin or super-admin account. The panel uses a tabbed single-page interface — click any item in the sidebar to load that section without a page reload.

ℹ Permissions: Each menu item below is gated by a permission key. Admins only see the menus assigned to them in Users & Roles. Super Admins see everything.

Dashboard

The landing page after login. It shows real-time business metrics:

  • Total bookings, total revenue, sold seats count.
  • Recent booking activity feed.
  • Date-range filter to narrow down statistics to a specific period.

Coach Services

Permission: coach-services

The live fleet monitor. Search for available coach services and manage seat availability in real time.

FieldDescription
From StationFilter by departure station (or "All").
To StationFilter by destination station (or "All").
Journey DatePick a date — defaults to today.
Coach TypeAll, AC, or Non-AC.

After clicking Search Buses, each matching schedule shows its interactive seat map. You can click any available seat to block it (e.g. for offline sales or maintenance) or click a blocked seat to unblock it. A Live toggle refreshes the seat map every 5 seconds so you always see current occupancy.

Creating a manual booking

  1. Select a Schedule.
  2. Enter Passenger Name, Phone, and Email.
  3. Enter Seat Numbers (comma-separated, e.g. A1,A2).
  4. Enter the Total Fare in BDT.
  5. Choose Payment Method (bKash, Nagad, Card, Cash, ZiniPay).
  6. Set the Status and submit.

Cancel Requests

Permission: cancel-requests

Lists all passenger-initiated cancellation requests that await your approval. Each row shows the PNR, passenger, contact, journey, bus, seats, fare, and request timestamp. Click Approve to confirm the cancellation — the booking status becomes CANCELLED and the seats are released for rebooking. Refunds are handled according to your own policy.

Customer App Overview

The React app is served from frontend/dist/ after building.

  • Search — select origin, destination, date, and optionally coach type (AC / Non-AC).
  • Seat map — interactive seat picker showing available, booked (M/F), and blocked seats. Seats are temporarily held for 2 minutes while the customer completes checkout.
  • Checkout — enter passenger details, apply a promo code, choose payment method, and confirm.
  • Payment — redirects to ZiniPay; on success the booking status is updated to SOLD and an SMS confirmation is sent.
  • My Tickets — authenticated customers can view all their bookings and request cancellations.
  • Offers — displays active promo codes from the admin panel.
  • Maintenance mode — if enabled in Admin → Site Settings, the app shows a maintenance page (site-settings endpoint remains accessible).

User Manual

This section walks you through the day-to-day usage of SonyaBus — both the Admin Panel and the Customer App.

Admin Panel Manual

Dashboard

The dashboard gives you a quick overview of your business — total bookings, revenue, sold seats, and recent activity. Use the date-range filter to view reports for a specific period.

Managing Stations

  1. Go to Stations in the sidebar.
  2. Click Add Station and enter the station name (e.g. "Dhaka", "Chittagong").
  3. Save. Stations are used as origin and destination points when creating routes.

Managing Coaches (Buses)

  1. Go to Coaches → Add Coach.
  2. Enter the coach name, registration number, coach type (AC / Non-AC / Sleeper), and total seats.
  3. Set the seat layout: 2+2 (standard), 1+2 (premium), or 1+1 (sleeper). The seat map preview updates automatically.
  4. Save. The coach is now available to assign to schedules.

Managing Routes

  1. Go to Routes → Add Route.
  2. Select an Origin and Destination station.
  3. (Optional) Add boarding and dropping points with their times.
  4. Save. Routes are reusable across multiple schedules.

Creating Schedules

  1. Go to Schedules → Add Schedule.
  2. Select the Route, Coach, and set the departure date and time.
  3. Enter the ticket fare per seat.
  4. Choose the schedule status: Active (bookable) or Inactive (hidden from customers).
  5. Save. The schedule will now appear in customer search results.

Managing Bookings

The Bookings Logs page shows all customer reservations. You can:

  • View booking details — passenger info, seats, fare, payment status.
  • Create a manual booking on behalf of a customer.
  • Edit passenger details or seat assignments.
  • Cancel a booking (refund handled per your policy).

Customer-initiated cancellation requests appear under Cancel Requests. Review and approve them to process refunds.

Coach Services (Live Seat Map)

The Coach Services page shows real-time seat availability for each schedule. You can manually block or unblock seats (e.g. for maintenance or to hold seats for offline sales).

Promotions & Coupons

  1. Go to Coupons → Add Coupon.
  2. Enter the promo code (e.g. EID20), discount amount, and expiry date.
  3. Set usage limits (per user / total) if needed.
  4. Save. Customers can apply the code during checkout.

Reports

SonyaBus ships with 11 report types accessible from the Ticket Reports menu:

  1. Ticket Selling Report — all paid ticket sales by date, route, coach type, and payment method.
  2. Booking Report — active bookings (PAID, SOLD, BOOKED) with full status breakdown.
  3. Revenue Report — total revenue from paid bookings, split by AC / Non-AC and method.
  4. Passenger Report — passenger travel history with boarding, dropping, gender details.
  5. Seat Occupancy Report — per-schedule booked vs available seats and occupancy percentage.
  6. Cancellation Report — full cancellation log with booking date, route, and fare released.
  7. Ticket Cancel Report — cancelled tickets export with Excel and PDF support.
  8. Refund Report — online-payment cancellations eligible for refund with invoice IDs.
  9. Payment Report — payment transaction log broken down by method with amounts.
  10. Route-wise Sales Report — aggregated sales per route (bookings, seats, revenue ranked).
  11. Agent / Counter Sales — aggregated sales per operator with routes covered and revenue.

Every report supports filtering by date range and exporting as PDF or Excel.

Users & Roles

  • Super Admin — full access, including system settings and license.
  • Admin — access limited to menus granted in Menu Permissions. A null permissions list grants full admin access.
  • User — customer-only; cannot log into the admin panel.

To add an admin: go to Users & Roles → Add User, set the role to admin, and select which menu items they can access.

Site Settings

Under Site Settings (Super Admin only) you can update the site name, favicon, logo, footer text, SEO meta tags, and toggle Maintenance Mode.

Integrations & Gateways

Configure payment (ZiniPay), SMS, and mail settings from Integrations (Super Admin only). Each section includes a "Send Test" button to verify the connection before going live.

Customer App Manual

Searching for Buses

  1. Open the customer app and select your Origin and Destination.
  2. Pick a date and optionally filter by coach type (AC / Non-AC).
  3. Click Search. Available schedules appear with departure time, arrival time, fare, and available seats.

Selecting Seats

Choose a schedule to open the interactive seat map:

  • Available — seats you can select.
  • Booked — already sold (shown as M/F).
  • Blocked — unavailable (reserved by the operator).

Click available seats to select them. Seats are temporarily held for 2 minutes while you complete checkout — if you exceed the time, the seats are released.

Checkout & Payment

  1. Enter passenger details (name, phone, email).
  2. Apply a promo code if you have one — the discount is applied instantly.
  3. Review the total fare and click Pay Now.
  4. You will be redirected to the ZiniPay payment page. Complete the payment there.
  5. On success, you return to the app and the booking is confirmed. An SMS with your PNR and seat numbers is sent to your phone.

My Tickets

After logging in, go to My Tickets to view all your bookings. Each ticket shows the PNR, schedule details, seat numbers, fare, and status.

Cancelling a Ticket

  1. Open the ticket in My Tickets.
  2. Click Request Cancellation.
  3. The request is sent to the admin. You will receive an SMS notification once the admin approves it.
  4. Refunds are processed according to the operator's cancellation policy.

Offers

The Offers page lists all active promo codes from the admin. Copy a code and apply it during checkout to get the discount.

ZiniPay Payment Setup

  1. Create a merchant account at zinipay.com and obtain your API key.
  2. Set in backend/.env: 
    ZINIPAY_API_KEY=your_api_key_here
ZINIPAY_BASE_URL=https://api.zinipay.com
  3. Set in frontend/.env: 
    VITE_ZINIPAY_API_KEY=your_api_key_here
  4. Configure these callback URLs in your ZiniPay merchant dashboard:
    TypeURL
    Redirect (success/fail)https://your-backend.com/payment/callback
    Cancelhttps://your-backend.com/payment/cancel
    Webhook (async)https://your-backend.com/api/payment/webhook
ℹ Webhook security: The webhook endpoint re-verifies every payment directly with the ZiniPay API before updating the booking status. Raw webhook payloads are never trusted.

Mail / Password Reset

Password reset emails require a working SMTP configuration. Set the following in backend/.env:

MAIL_MAILER=smtp
MAIL_HOST=smtp.yourmailprovider.com
MAIL_PORT=587
MAIL_USERNAME=your@email.com
MAIL_PASSWORD=your_smtp_password
MAIL_ENCRYPTION=tls
MAIL_FROM_ADDRESS=noreply@yourdomain.com
MAIL_FROM_NAME="SonyaBus"

You can also update mail settings live from Admin → Integrations → Mail and send a test email to verify the connection.

ℹ Local testing: Set MAIL_MAILER=log to write emails to storage/logs/laravel.log instead of sending them.

Queue Worker & Cron

SMS notifications are dispatched as queued jobs (QUEUE_CONNECTION=database). You need a persistent queue worker process.

Start a worker (basic)

cd backend
php artisan queue:work --tries=3 --sleep=3

Recommended: Supervisor (Linux)

[program:sonyabus-worker]
process_name=%(program_name)s_%(process_num)02d
command=php /var/www/sonyabus/backend/artisan queue:work --tries=3 --sleep=3
autostart=true
autorestart=true
numprocs=1
redirect_stderr=true
stdout_logfile=/var/www/sonyabus/backend/storage/logs/worker.log

Laravel Scheduler (optional)

Add this cron entry on the server to run the Laravel scheduler every minute:

* * * * * cd /var/www/sonyabus/backend && php artisan schedule:run >> /dev/null 2>&1

Updating SonyaBus

  1. Back up your database: mysqldump sonyabus > sonyabus_backup.sql
  2. Replace the backend/ and frontend/src/ files with the new version (keep your .env files).
  3. Run composer install --no-dev --optimize-autoloader in backend/.
  4. Run php artisan migrate to apply any new database migrations.
  5. Run php artisan config:clear && php artisan cache:clear && php artisan view:clear.
  6. In frontend/, run npm install && npm run build.
  7. Restart your queue worker: php artisan queue:restart.

Troubleshooting

General Issues

SymptomLikely cause & fix
500 Internal Server Error on all pages Storage or cache directory not writable. Run chmod -R 775 storage bootstrap/cache. Also check APP_KEY is set.
Blank white React app VITE_API_BASE_URL is wrong or the backend is unreachable. Open browser DevTools → Network and check the first API call.
CORS errors in browser console Add your frontend domain to config/cors.php → allowed_origins, then run php artisan config:clear.
Payment callback lands on error page Verify APP_URL and APP_FRONTEND_URL in backend/.env match your live domain. Callback URLs in ZiniPay dashboard must also match.
SMS not sending Check queue worker is running (php artisan queue:work). Verify API key and gateway URL in Admin → Integrations → SMS. Use "Send Test SMS" to diagnose.
Password reset email not arriving Check SMTP credentials in .env or Admin → Integrations → Mail. Use "Send Test Email" to verify. Check spam folder.
Admin dashboard shows blank tabs Run php artisan view:clear and hard-refresh the browser (Ctrl+Shift+R).
Seat map shows all seats unavailable Check that the schedule date is today or in the future. Past schedules show all seats as expired.
License wizard: "ENVATO_ITEM_ID is not configured" Add your CodeCanyon item ID after ENVATO_ITEM_ID= in the .env file and run php artisan config:clear.
License wizard: "Invalid or expired personal token" Envato personal token expire হয়ে থাকতে পারে। build.envato.com থেকে নতুন token তৈরি করুন।
License wizard: "purchase code is for a different product" You are using a purchase code from a different CodeCanyon item. Use the purchase code for SonyaBus.

Common cPanel Issues

ProblemSolution
Opening the site on cPanel shows Object not found or the index The subdomain Document Root is set incorrectly. cPanel → Domains → set the Document Root for api.yourdomain.com to public_html/api/public — not public_html/api.
composer: command not found composer is not available in the Terminal. Run composer install --no-dev on your local machine and upload the project including the vendor/ folder. Or use your hosting provider's Composer Manager.
PHP version error: requires PHP 8.2 cPanel → MultiPHP Manager → select your domain → set PHP version to 8.2 or higher.
.env file is not visible in File Manager cPanel File Manager → Settings → check "Show Hidden Files (dotfiles)". .env is a hidden file.
Database connection error in the wizard In cPanel MySQL, the database user must be assigned to the database. cPanel → MySQL Databases → "Add User to Database" → grant ALL PRIVILEGES. DB_HOST is usually localhost (not 127.0.0.1).
storage/logs write permission error cPanel File Manager → public_html/api/storage → right click → Change Permissions → set from 755 to 775. Apply recursively.
React app shows 404 on route refresh The public_html/app/.htaccess file is missing or incorrect. Use the .htaccess content from Step 8 of the installation guide.
SSL/HTTPS mixed content warning Both APP_URL and APP_FRONTEND_URL must start with https://. cPanel → SSL/TLS → install a Let's Encrypt certificate.
Cron job is not working Run which php in the Terminal to find the correct PHP path. Use that path in the cron command, e.g.: /opt/cpanel/ea-php82/root/usr/bin/php
