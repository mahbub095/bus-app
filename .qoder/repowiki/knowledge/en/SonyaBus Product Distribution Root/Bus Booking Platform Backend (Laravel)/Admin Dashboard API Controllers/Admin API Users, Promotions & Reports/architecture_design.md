Three sibling controllers under `App\Http\Controllers\API\Admin`, each extending `BaseAdminApiController` and composing the shared `FormatsAdminResources` concern for consistent JSON serialization.
- `UserApiController` handles full CRUD over the `User` model with role-based guards (Super Admin only for create/update/delete of admin accounts) and menu-permission validation against `User::MENU_KEYS`.
- `PromotionApiController` provides CRUD over `Promotion` coupon codes, centralizing validation rules and payload normalization in protected `rules()` / `payload()` helpers.
- `ReportApiController` is a thin façade over `ReportFilterService` and `ReportDataService`; it declares an explicit `TYPES` whitelist, delegates filter validation to the filter service, and dispatches per-report logic via a `match` on `$type` into `bookingsPreview` / `aggregatedPreview` / `seatOccupancyPreview` helpers that cap rows (`ROW_LIMIT = 500`, `SCHEDULE_ROW_LIMIT = 200`) before returning `{summary, rows, total_count}`. Export endpoints (Excel/PDF) live outside this module on web routes; this controller only serves JSON previews consumed by Blade report pages.
