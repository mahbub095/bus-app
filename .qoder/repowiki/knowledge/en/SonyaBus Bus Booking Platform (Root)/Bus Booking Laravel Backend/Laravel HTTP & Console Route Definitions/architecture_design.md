Three Laravel route files partition the request surface by client:
- `api.php` — JSON API consumed by the React frontend under `/api/*`, split into public read endpoints (stations, search, promotions), guest auth with a `throttle:10,1` rate limit, Sanctum-authenticated customer routes (bookings, seats hold/release, profile), plus external webhook/callback endpoints (`/payment/webhook`, `/bookings/public/{id}`). A shared `CheckMaintenanceMode` middleware gates most groups; `/site-settings` is always open.
- `web.php` — Blade-driven admin dashboard and install wizard. The `/install/*` flow bypasses license checks to bootstrap the app. Admin routes are grouped under `auth` + `admin` middleware, then subdivided by `menu_permission:<resource>` (coach-services, bookings, cancel-requests, stations, buses, routes, schedules, promotions, users) and `super_admin` for license/site-settings/gateway configuration. AJAX helpers live at `/admin/api/*`.
- `console.php` — minimal Artisan command registration (the default `inspire` command).

Dependency direction is one-way: routes import controllers from `App\Http\Controllers\API\`, `App\Http\Controllers\Admin\`, `App\Http\Controllers\Install\`, and `App\Http\Controllers\PaymentController`; business logic lives in `App\Services\` as documented in the web.php comment block. No cross-route dependencies exist between the three files.
