Three-layer leaf module following Laravel's MVC + Services pattern:
- `BookingController` (API layer) handles HTTP validation, authorization checks, and delegates all business logic to `BookingService`; it also coordinates `SeatMapService` for seat holds/releases and `ZinipayService` for payment invoicing.
- `BookingService` is the domain core: shared between customer and admin flows (`createForCustomer`, `createForAdmin`, `cancelForCustomer`, `formatForApi`). It owns transactional seat locking via `DB::transaction` with `lockForUpdate()`, fare calculation (with optional promo-code discount), status resolution, ZiniPay invoice attachment, and SMS verification dispatch. Seat availability is derived from `SeatMapService` using a snapshot of active bookings (PAID/SOLD/BOOKED plus PENDING within 10 minutes).
- `Booking` Eloquent model is thin: fillable attributes, decimal cast on `total_fare`, belongsTo relationships to `Schedule` and `User`, and an accessor `getPnrAttribute` that derives a passenger ticket reference (`SE` + zero-padded id).
Dependency direction is one-way: Controller → Service → Models + external services (SeatMapService, SmsGatewayService, ZinipayService). The controller returns plain arrays shaped by `formatForApi` rather than raw models.
