Two independent frontends share one Laravel backend:
- Backend (`backend/`): Laravel 12 project with `routes/api.php` exposing the public customer JSON API (Sanctum tokens) served to the React SPA, and `routes/web.php` serving Blade views for the admin panel plus public payment callback routes. Controllers in `App\Http\Controllers\API\*` are thin request handlers delegating to `App\Services\*` business classes (BookingService, SeatMapService, RouteService, SiteSettingsService, ZinipayService, SmsGatewayService, ReportDataService, etc.). Admin controllers under `Admin\*` use session auth and call an `AjaxController` for `/admin/api/*` JSON endpoints.
- Models live in `app/Models/` (Booking, Schedule, Route, Bus, Station, User, Promotion, License, SiteSetting, SmsConfig) with corresponding Eloquent migrations in `database/migrations/` and seeders in `database/seeders/`.
- Middleware enforces access: `EnsureUserIsAdmin`, `EnsureUserIsSuperAdmin`, `EnsureUserHasMenuPermission`, `CheckMaintenanceMode`, `EnsureLicenseIsActivated`.
- Frontend (`frontend/`): Vite + React 19 SPA (`src/components/*`) consuming the `/api/*` endpoints; communicates with the backend via fetch/XHR and handles ZiniPay redirects through `zinipay.js`.
- Build & install: Composer scripts (`composer setup`, `composer dev`) orchestrate `artisan key:generate`, `migrate`, `npm install`, and `npm run build`; the admin assets are compiled via Vite from `resources/js/admin/*.js` and Blade partials compose the dashboard UI.
