Three parallel feature verticals share a uniform Controller → Service → Model layering with one-way dependencies:
- Site settings: `SiteSettingsApiController` (public JSON API) and `SiteSettingsController` (admin form) delegate to `SiteSettingsService`, which reads/writes key/value pairs through the cached `SiteSetting` model (`getAllCached` with a 5-minute `site_settings_all` cache).
- Licensing: `LicenseController` exposes `info()` and `reVerify()` against `LicenseService`, which validates UUID format, supports local bypass (`ENVATO_SKIP_VERIFY`) and seller bypass (`DEFAULT_BYPASS_CODE`), calls Envato's author-sale/buyer-purchase REST endpoints via Laravel HTTP client with retry/timeout, enforces a per-code domain limit of 5, persists activation state in the `license` table and `.env` via `EnvFileWriter`, and caches activation status for 24 hours.
- Gateways: `GatewaySettingsController` routes SMS/Mail/ZiniPay updates to `GatewaySettingsService`, which writes settings both to the `sms_configs` table (SMS driver config) and to `.env`/`SiteSetting` rows; `SmsGatewayService` dispatches outbound SMS through a driver switch (`bulksmsbd`, `smsnetbd`, `get_query`, custom form) using normalized Bangladesh phone numbers.
Dependency direction is strictly one-way: Controllers depend on Services; Services depend on Models and shared infrastructure (`EnvFileWriter`, `Mail`, `Http`, `Cache`). There are no cross-feature dependencies between the three verticals except shared `SiteSetting` for mail/ZiniPay config.
