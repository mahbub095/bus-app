Three Laravel route files partition the request surface by client with one-way dependency on controllers under `App\Http\Controllers\` and business logic in `App\Services\`:
- `api.php` — JSON API consumed by the React frontend. A top-level `/site-settings` is always open; read-only endpoints (`/stations`, `/search`, `/promotions*`) are wrapped in `CheckMaintenanceMode`; guest auth routes (`/auth/register|login|forgot-password|reset-password`) use `throttle:10,1`; external webhooks live at `/payment/webhook` and `/bookings/public/{id}`; authenticated customer routes under `['auth:sanctum', CheckMaintenanceMode]` cover logout/me/password, bookings CRUD/pay/cancel, and seat hold/release; a nested `prefix('admin')` group mirrors every resource as Sanctum-token-authenticated REST endpoints gated by `api_menu:<feature>` middleware.
- `web.php` — Blade-driven admin dashboard plus install wizard. The `/install/*` flow bypasses license checks to bootstrap the app. Admin routes are grouped under `['auth', 'admin']`, then subdivided per resource via `menu_permission:<resource>` (coach-services, bookings, cancel-requests, stations, buses, routes, schedules, promotions, users) and a nested `super_admin` middleware for user creation. AJAX helpers sit under `/admin/api/*`. Reports are a large single controller with preview/export endpoints per report type.
- `console.php` — minimal Artisan command registration (default `inspire`).
No cross-route dependencies exist between the three files; each file is self-contained.
