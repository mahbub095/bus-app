Three-layer leaf module inside `app/`:
- Models (`Models/Bus.php`, `Route.php`, `Schedule.php`, `Station.php`) are thin Eloquent entities with `$fillable`, `$casts`, and relationships (`Bus->hasMany Schedule`, `Schedule->belongsTo Bus/Route`, `Route->belongsTo Station` via `departure_station_id`/`arrival_station_id`).
- Controllers split by audience: `API/StationController` (extends a shared `BaseController`) exposes a read-only station list; `Admin/*` controllers extend `BaseAdminController` and handle CRUD with request validation, file-to-base64 logo handling, and flash redirects.
- Services in `Services/` encapsulate domain logic: `CoachServicesService` orchestrates schedule search across routes/stations/dates/coach types and delegates seat-map formatting to `SeatMapService`; `RouteService` centralizes route JSON parsing and duplicate detection; `SeatMapService` owns all seat-code generation (layouts `2+2`, `2+2_last5`, `1+2`, `sleeper`, plus custom `seat_layout_grid`), blocked-seat toggling, cache-backed hold/release, boarding/dropping point formatting, and pricing breakdowns.
Dependency direction is one-way: Controllers → Services → Models. The public API surface of the service layer is typed via PHPDoc return annotations (e.g. `Collection<int, array<string, mixed>>`, `array{success: bool, status: int, body: ...}`). Seat availability uses Laravel Cache keyed by `schedule_holds:{id}` with per-user expiry timestamps.
