Single entry `src/main.jsx` mounts a root `App.jsx` that owns all global state (auth token/user, active tab, toast queue, site settings, API base URL) and renders feature components under `src/components/` based on an `activeTab` (`home`, `cancel`, `offers`, `profile`) — there is no client-side router. Backend discovery runs at mount: it probes the configured `VITE_API_BASE_URL`, then falls back to same-origin `/api`, `localhost:8000/api`, and Laragon-style subdirectory paths, persisting the winner in `localStorage` under `sonyabus_api_base`. Auth state lives in `sonyabus_auth_token` / `sonyabus_auth_user`; Bearer tokens are attached via an `authHeaders()` helper used by every `fetch` call. Payment integration is isolated in `src/zinipay.js`, which calls the external ZiniPay REST API directly (using `VITE_ZINIPAY_API_KEY`) and bridges redirect/query parameters back into app state via `handleZiniPayRedirect`. The `components/` folder is flat with one component per file; components receive props and do not share a context/store. Styling is plain CSS driven by `theme-variables.css` plus per-component `.css` files. Dev proxying is centralized in `vite.config.js`, forwarding `/api`, `/uploads`, and Laragon-specific `/backend/public/*` routes to the configured backend target, with a 502 fallback when the primary proxy target is unreachable so the frontend's own probe logic can kick in.
